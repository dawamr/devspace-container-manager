# TanStack Start Scaffolding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold a working TanStack Start project at the repo root with an `app/` source root organized as a modular monolith (3-layer clean architecture per module: domain / infrastructure / presentation), ready to receive Sprint 1 feature work (auth, users, projects, RBAC) without any business logic written yet.

**Architecture:** Use the official `@tanstack/cli` to generate the blank TanStack Start template directly into the existing repo (it preserves unrelated existing files), then rename its `src/` root to `app/` and reconfigure the three places that hardcode `src` (`tsconfig.json` paths, `package.json` imports, `tsr.config.json`, and the `tanstackStart()` Vite plugin option). On top of that skeleton, add empty-but-real module/shared folders and two small pieces of real infra config (env validation, Drizzle config) — no schema tables, no auth logic, no CRUD.

**Tech Stack:** TanStack Start (React 19), TanStack Router file-based routing, Vite 8, pnpm, TypeScript strict, Zod (env validation), Drizzle Kit (config only, no schema yet), dotenv.

**Reference:** `docs/superpowers/specs/2026-08-12-tanstack-start-scaffolding-design.md`

## Verified facts (do not re-derive — these were confirmed by actually running the tools)

- Scaffold command: `pnpm dlx @tanstack/cli@latest create . --blank -y --force` run from the repo root. Verified safe to run in a non-empty git repo: it does **not** re-init git or wipe unrelated files (tested with an existing commit + unrelated `docs/spec.md` file, both survived). It **does overwrite `.gitignore`** unconditionally with its own (broader) template — this is fine, the generated one is a superset of what we need.
- Generated files (blank template, TypeScript, file-router mode): `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `tsconfig.json`, `tsr.config.json`, `vite.config.ts`, `.vscode/settings.json`, `.cta.json`, `README.md`, `.gitignore`, and `src/router.tsx`, `src/styles.css`, `src/routes/__root.tsx`, `src/routes/index.tsx`, `src/routeTree.gen.ts`.
- Renaming `src/` → `app/` requires editing **four** places (verified by actually doing the rename and getting `pnpm build` to fail, then pass once all four were fixed):
  1. `tsconfig.json` → `compilerOptions.paths`
  2. `package.json` → `imports` (the `#/*` subpath import map)
  3. `tsr.config.json` → add explicit `routesDirectory` / `generatedRouteTree` (used by the standalone `tsr generate` CLI, which defaults to `./src/routes` relative to repo root)
  4. `vite.config.ts` → `tanstackStart({ srcDirectory: 'app' })` (used by the Vite plugin itself at dev/build time — this is a **separate** config path from `tsr.config.json` and defaults to `"src"` independently; omitting this causes `vite build` to fail with `Could not resolve entry for router entry: router in .../src`)
- After all four edits, `pnpm generate-routes` correctly writes `app/routeTree.gen.ts`, and `pnpm build` / `pnpm dev` both work (confirmed: dev server returns HTTP 200, build produces `dist/client` and `dist/server` with no errors).

### Task 2: Move the source root from `src/` to `app/` and fix the four places that reference it

**Files:**
- Modify: `tsconfig.json` (paths), `package.json` (imports), `tsr.config.json` (routesDirectory/generatedRouteTree), `vite.config.ts` (tanstackStart srcDirectory option)
- Move: `src/` → `app/` (entire directory)

- [ ] **Step 1: Move the directory**

Run:
```bash
mv src app
rm -f app/routeTree.gen.ts
```
(We delete the stale generated route tree; it gets regenerated in Step 5.)

- [ ] **Step 2: Update `tsconfig.json` path aliases**

In `tsconfig.json`, change:
```json
    "paths": {
      "#/*": ["./src/*"],
      "@/*": ["./src/*"]
    },
```
to:
```json
    "paths": {
      "#/*": ["./app/*"],
      "@/*": ["./app/*"]
    },
```

- [ ] **Step 3: Update `package.json` subpath imports**

In `package.json`, change:
```json
  "imports": {
    "#/*": "./src/*"
  },
```
to:
```json
  "imports": {
    "#/*": "./app/*"
  },
```

- [ ] **Step 4: Point the standalone route-tree generator at `app/`**

Replace the full contents of `tsr.config.json` with:
```json
{
  "target": "react",
  "routesDirectory": "./app/routes",
  "generatedRouteTree": "./app/routeTree.gen.ts"
}
```
(Without this, `pnpm generate-routes` looks for `./src/routes` and fails with `ENOENT`.)

- [ ] **Step 5: Point the Vite plugin at `app/`**

In `vite.config.ts`, change:
```ts
  plugins: [tanstackStart(), viteReact()],
```
to:
```ts
  plugins: [tanstackStart({ srcDirectory: 'app' }), viteReact()],
```
(This is a separate config path from `tsr.config.json` — the Vite plugin resolves its own entry points and defaults to `srcDirectory: "src"` regardless of `tsr.config.json`. Skipping this makes `pnpm build` fail with `Could not resolve entry for router entry: router in .../src`.)

- [ ] **Step 6: Regenerate the route tree and verify it lands in `app/`**

Run: `pnpm generate-routes`
Expected: no errors; run `find . -name "routeTree.gen.ts" -not -path "./node_modules/*"` and confirm the only match is `./app/routeTree.gen.ts`.

- [ ] **Step 7: Verify the production build works from the new location**

Run: `pnpm build`
Expected: both `vite build` (client) and the SSR build succeed, ending in `dist/server/server.js` being written, no `Could not resolve entry` error.

- [ ] **Step 8: Verify the dev server still boots**

Run: `pnpm dev &`, wait ~3s, `curl -sS -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/`, then `pkill -f "vite dev"`.
Expected: `HTTP 200`.

- [ ] **Step 9: Commit**

```bash
git add -A
git commit -m "chore: move source root from src/ to app/"
```

### Task 4: Add zod-validated environment config

**Files:**
- Create: `app/shared/config/env.ts`
- Create: `.env.example`

- [ ] **Step 1: Add the dependencies**

Run: `pnpm add zod dotenv`
Expected: exit code 0; `package.json` now lists `zod` and `dotenv` under `dependencies`.

- [ ] **Step 2: Write `app/shared/config/env.ts`**

```ts
import 'dotenv/config'
import { z } from 'zod'

const envSchema = z.object({
  PORTAINER_URL: z.string().url(),
  PORTAINER_API_KEY: z.string().min(1),
  DATABASE_URL: z.string().min(1),
  SESSION_SECRET: z.string().min(1),
})

export const env = envSchema.parse(process.env)
```

- [ ] **Step 3: Write `.env.example`**

```
PORTAINER_URL=
PORTAINER_API_KEY=
DATABASE_URL=
SESSION_SECRET=
```

- [ ] **Step 4: Verify the file type-checks**

Run: `pnpm exec tsc --noEmit`
Expected: exit code 0, no type errors. (This only type-checks — it does not execute `env.ts`, so a missing real `.env` file at this stage is fine; `envSchema.parse` only runs when something actually imports `env.ts`, which nothing does yet.)
